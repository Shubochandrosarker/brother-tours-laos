# 02 - Assumptions and Missing Facts

## Observed facts (E2)

- Production is `https://www.brothertours.com/`; the apex redirects to `www`.
- Production currently uses Rank Math sitemap output; the requested future owner is SEOISTIC.
- Staging is publicly accessible, blocks all crawlers in `robots.txt`, and exposes an indexable/canonical homepage plus a public WordPress sitemap index.
- Production publishes standalone visa, accommodation, guide, driver, rental and ticketing services outside the requested tour-only scope.
- The inspected bundle is not a Git repository. Operations API is `1.0.0` with `bt-ops/v1`, not the reported `1.1.0` / `bridgistic-api/v1` release.

## MISSING - OWNER INPUT REQUIRED

- Final approver name and authority; target launch date and deployment window.
- Legal/public business name, street address, phone, WhatsApp, primary email, hours, founding year, licence details, logo and official profiles.
- Whether the live `enquiry@brothertours.com`, `ken@brothertours.com`, and other published addresses are authoritative; the live `hello@brothertors.com` typo must not be guessed.
- Authoritative price, currency, availability, itinerary, inclusions, exclusions, accommodation, accessibility, safety and cancellation facts for every tour.
- Final tour categories, priority tours/destinations and whether experiences warrant standalone pages.
- Destination and legal canonical slugs, plus disposition of every out-of-scope service.
- SEOISTIC source/version/settings; active plugin list; authoritative redirect layer; cache/CDN/consent/analytics stack.
- GSC, GA4, backlink, server-log, current redirect and booking/CRM exports.
- Legal approval for privacy, terms, booking and cancellation content.

`MISSING` never means zero. No unresolved URL receives a final redirect or removal action before evidence and Gate A approval.
